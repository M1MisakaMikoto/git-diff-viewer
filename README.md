# Git Diff Viewer

按目录浏览完整 Git 项目树与版本差异的 VS Code 扩展。它把“工作区对比版本”“两个版本互相对比”和“暂存区对比工作区”统一成一棵类似资源管理器的文件树：普通文件正常展示，有差异的文件附带状态，点击差异文件后直接进入 VS Code 原生 diff 编辑器。

## 解决什么问题

VS Code 自带的 Git 变更列表更偏向工作区状态，版本之间的 compare 又通常只给出文件列表或单独的两个编辑器。这个扩展把两者结合起来：

- 从目录开始看，目录会明确显示“新增”“修改”或“修改 + 新增”。
- 逐层展开目录，最后看到文件自身的 `A / M / D / R` 状态。
- 点击文件直接打开左右对照的原生 diff，左侧是选定的 Git 版本或暂存区，右侧是工作区或目标版本。
- 不需要先切换分支、暂存文件或打开额外的 compare 页面。

## 功能

- 目录聚合状态：绿色表示只有新增，黄色表示只有修改，描述中显示“修改 + 新增”和文件数量。
- 完整文件树：未修改的文件和目录与变更文件一起显示，未修改文件可直接打开。
- 文件状态：新增 `A`、修改 `M`、删除 `D`、重命名 `R`、复制 `C`、类型变更 `T`、冲突 `U`。
- 未跟踪文件自动计入“新增”。
- 支持工作区与 `HEAD`、分支、标签、提交或 `HEAD~1` 等版本表达式对比。
- 支持任意两个版本互相对比。
- 支持“暂存区 ↔ 工作区”对比，交互方式与原生 Source Control 的文件列表一致。
- 支持多根工作区中的多个 Git 仓库，每个仓库分别记忆自己的对比范围。
- 文件保存、创建、删除和重命名后自动刷新，也可以在标题栏手动刷新。

## 使用

1. 打开一个包含 Git 仓库的 VS Code 工作区。
2. 点击活动栏中的 **Git 版本对比** 图标。
3. 点击标题栏的对比按钮，选择对比范围。
4. 展开目录节点；有差异的文件会在点击后打开 diff，无差异文件会直接打开源码。

### 安装 VSIX

在项目根目录生成安装包后执行：

```powershell
code --install-extension ".\git-diff-viewer-0.1.0.vsix"
```

默认对比范围是 `HEAD ↔ 工作区`。版本选择器中可以：

- 选择本地分支、远程分支、标签或最近提交。
- 手动输入提交哈希、分支名、标签名或 `HEAD~2`。
- 在“两个版本对比”中先选左侧基准版本，再选右侧目标版本。

## 命令

在命令面板中搜索“Git 版本对比”：

| 命令 | 说明 |
| --- | --- |
| 选择对比范围 | 统一的对比范围选择入口 |
| 工作区与 HEAD 对比 | 对比 HEAD 和当前工作区 |
| 工作区与指定版本对比 | 选择任意版本作为基准 |
| 两个版本对比 | 对比任意两个版本 |
| 暂存区与工作区对比 | 对比 index 和当前工作区 |
| 刷新 | 重新读取 Git 变更 |

文件节点还提供“打开差异”“打开文件”和“复制相对路径”操作。

## 配置

`gitDiffViewer.autoRefresh`

默认开启。文件变化后自动刷新变更树。仓库很大或自动刷新过于频繁时可以关闭。

## 开发

```powershell
npm.cmd install
npm.cmd test
```

在 VS Code 中打开项目后按 `F5`，会启动扩展开发宿主。

项目结构：

- `src/git.ts`：Git 仓库发现、版本列表、变更读取和版本内容读取。
- `src/model.ts`：`--name-status -z` 解析、目录聚合和状态文本。
- `src/treeProvider.ts`：目录/文件 TreeView 与状态图标。
- `src/controller.ts`：对比状态、版本选择、diff 打开、自动刷新。
- `src/contentProvider.ts`：任意 Git 版本内容的虚拟文档。

## 说明

- 需要本机可执行的 `git`。
- diff 使用 VS Code 原生 diff 编辑器，默认由 VS Code 决定并排或行内显示。
- 二进制文件会交给 Git 读取，但 VS Code 的文本 diff 编辑器无法提供有意义的二进制内容对照。
- 完整文件树基于目标版本的 Git 文件集合，包含已跟踪文件和未被 `.gitignore` 忽略的未跟踪文件。
